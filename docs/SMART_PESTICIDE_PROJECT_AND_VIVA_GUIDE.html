Smart Pesticide Residue Detection System

Complete Technical Software Architecture, Multi-Sensor TinyML Pipeline & Viva Defense Guide
Department: Electronics & Telecommunication (ENTC) Target: STM32F407VET6 (ARM Cortex-M4) Project Type: ISE-I Mega Project / Research

1. Executive Summary & System Purpose

This project develops a low-cost, portable multi-sensor embedded screening system for fruit quality assessment and estimated pesticide residue risk. Operating entirely at the edge without cloud dependency, it combines visual computer vision (OV2640 camera), surface colorimetry (TCS34725 RGB), volatile organic compound (VOC) gas detection (MQ135), wash-water electro-chemical sensing (pH probe), and environmental normalization (DHT22 Temperature & Humidity). The complete inference runs locally on an STM32F407VET6 microcontroller using TensorFlow Lite for Microcontrollers (TFLM).

3. The Big Technical Challenge: No Public Pesticide Dataset

How did we solve the lack of a commercial multi-sensor pesticide dataset?
In real-world agricultural research, laboratory GC-MS / LC-MS chromatography tests cost thousands of dollars per sample. No open-source dataset exists that maps raw MQ135 ADC voltages, TCS RGB values, and pH wash water directly to chemical pesticide concentrations for embedded MCUs.

Our Solution: Two-Tier Machine Learning Architecture
  1. Model 1 & 3 (Computer Vision - Trained on 8,457 real images): Trained on public benchmark datasets (FruitNet + AgriFreshNET + Mendeley Quality sets) for 5 fruits (Apple, Banana, Guava, Tomato, Brinjal). Outputs Fruit Class, Freshness, Quality Grade, and Shelf Life.
  2. Model 2 (Multi-Sensor Fusion - Synthetic Domain Modeling & Normalization): We developed a rule-based parametric synthesizer that models known biochemical pesticide interactions (e.g., organophosphate wash water acidification, VOC vapor elevation on MQ135, and RGB color shifts). We trained a multinomial logistic regression classifier on normalized sensor features with environmental compensation from DHT22.

4. End-to-End Software & Machine Learning Pipeline

The firmware execution loop executes synchronously every 2 seconds on the ARM Cortex-M4:

  1. Image Capture & Preprocessing:
    • OV2640 captures a 160×120 RGB565 frame directly into SRAM via DCMI DMA.
    • Center crop 120×120 extracts the region of interest; bilinear decimation resizes it to 80×80×3.
    • Zero-centered INT8 quantization converts RGB pixels: int8_val = pixel - 128.
  2. Model 1 Vision Inference (TinyML TFLM):
    • MobileNet-derived compact CNN running CMSIS-NN SIMD quantized kernels.
    • Computes 8 output heads: 5-class Fruit logits, 2-class Condition, 3 Quality heads, 3 Shelf-life stage heads.
    • Includes a trained Background Rejection Head to distinguish empty scenes from real fruits.
  3. Presence & Detail Verification:
    • Laplacian spatial variance verifies that an actual object with edge textures is present.
    • Empty/featureless backgrounds are cleanly suppressed to Fruit: NOFRUIT/UNKNOWN without random guessing.
  4. Model 2 Sensor Fusion & Estimated Pesticide Risk:
    • Reads TCS34725 (R, G, B, C), MQ135 (ADC counts), pH (mV to pH conversion), and DHT22 (T, RH).
    • Generates derived ratio features: R/C, G/C, B/C, and ln(MQ135).
    • Executes feature normalization: z = (x - mean) / scale.
    • Computes multi-class softmax logits to predict Estimated Pesticide Risk: LOW, MEDIUM, or HIGH.
  5. OLED & Alert Reporting:
    • Outputs the 8-row clean status buffer to the SSD1306 display via I2C.
    • Triggers buzzer/LED alert pulse on PB14 if HIGH pesticide risk or image rejection occurs.

7. Viva Defense & Examiner Q&A (Ratta / Preparation Section)

Q1. Why are you using multiple sensors when camera can already classify fruits?
Answer: "Camera vision only captures surface appearance, color, and physical defects. Pesticide chemical residues are invisible to standard RGB cameras. By fusing the camera with MQ135 (which detects volatile organic pesticide vapors), pH (which detects chemical wash-water shifts), and TCS34725 (micro-color surface staining), our system performs multi-modal feature fusion for a comprehensive food-safety screening."
Q2. Where did you get the dataset for pesticide risk?
Answer: "Commercial pesticide residue analysis requires expensive laboratory chromatography (GC-MS/LC-MS). Because no public embedded multi-sensor pesticide dataset exists, we used a two-tier ML strategy: Model 1 was trained on 8,400+ real fruit images from benchmark datasets (FruitNet and AgriFreshNET). Model 2 uses biochemical domain modeling to synthesize pesticide interaction ranges across VOCs, pH shifts, and color metrics, normalized with environmental compensation (DHT22)."
Q3. Why does the display say 'NOFRUIT/UNKNOWN' when nothing is placed in front of the camera?
Answer: "Standard classification models always force an output among the trained classes, which would cause an empty table to be falsely classified as Guava or Apple. To solve this, we implemented a dual-stage presence filter: a Laplacian spatial detail variance check combined with a specialized background rejection head. If no fruit is present or the confidence is low, the system conservatively reports UNCERTAIN rather than outputting false information."
Q4. How did you fit a deep learning vision model into just 512 KB Flash and 128 KB RAM?
Answer: "We utilized INT8 post-training quantization, which reduces model weights by 4x compared to float32. In firmware, we used ARM CMSIS-NN SIMD instructions and split the memory layout: TFLM persistent memory (54 KB) was placed into Core Coupled Memory (CCMRAM), while activations and camera DMA buffers were placed in SRAM1 with buffer reuse, achieving 85% Flash and 82% RAM utilization."
Q5. What is the role of the pH and MQ135 sensors?
Answer: "When fruit is washed, acidic or alkaline chemical residues dissolve into the wash water, causing a measurable shift on the analog pH probe. Simultaneously, organophosphate and synthetic pesticide residues emit volatile organic vapors that alter the conductivity of the tin dioxide (SnO2) sensing layer in the MQ135 gas sensor. The microcontroller samples both via 12-bit ADC and passes them to the risk model."
Q6. What micro-controller architecture and libraries are running on the board?
Answer: "We are using an STM32F407VET6 running an ARM Cortex-M4 core at 168 MHz with Hardware Floating Point Unit (FPU). The software uses bare-metal C/C++ with CMSIS-Core, CMSIS-NN, and TensorFlow Lite for Microcontrollers (TFLM). Camera frames are transferred via DCMI with DMA2, and sensors communicate over I2C and 12-bit ADC."
